# i18n

**Tier:** core (portable C11) · **Features:** [37 Globalization](../../../docs/features/37-Globalization/README.md) ·
**Tests:** [`test/`](test/) (2 suites: `i18n`, `i18n_date`)

Translation lookup, plural rules, the `{n}` formatter and UTF-8 helpers. English is the source
text and has no table: a lookup without a catalog, or for a text the catalog lacks, gives the
English back. Regions, dates and numbers are in `i18n_date.h`.

- **Key:** `i18n_hash(ctx, english)`, 32-bit FNV-1a over the context, one 0x04 byte, then the
  English (only the English without a context). A catalog is a table sorted by that hash plus a
  string block (`i18n_catalog_t`); `i18n_text()` and `i18n_plural()` binary-search it.
- **Plurals:** CLDR 48 cardinal rules for whole numbers (`i18n_plural_category()`), the
  categories a rule has in CLDR order (`i18n_plural_forms()`, also the order of a plural entry's
  forms and of `msgstr[i]`), and the rule for a locale (`i18n_plural_rule()`).
- **Formatter:** `i18n_format()` / `I18N_FORMAT()` know only `{0}`..`{9}`, `{{` and `}}`; a
  translation is never a printf format. A full buffer is cut on a whole UTF-8 character.
  `i18n_format_fit()` puts a name into a sentence whose own words must never be cut: the name is
  shortened with "…" instead, the room shared by every `{0}` the sentence holds (Smart Home's note,
  BL-171).
- **UTF-8:** `i18n_utf8_fit/copy/chars/valid`, strict and safe on any input.
- **Language packs** (docs/features/37 language-packs.md): `python tools/i18n.py pack --version <V>
  --out <dir> [--key <pem>] [--release]` writes one `<locale>.robolang` per `.po` (signed with
  `espsecure` when a key is given). `catalogs/i18n_template_gen.c` (generated by `build`, declared
  in `i18n/i18n_pack.h`) holds the firmware's own template fingerprint and entry count, which a
  pack is compared against; a build with `I18N_NO_BUILTIN` has an empty built-in table. The
  frozen fixture pack is `test/pack_fixture_v1.h` (never edited).
- **Built-in catalogs:** `catalogs/i18n_catalogs_gen.c` is generated by `tools/i18n.py build`
  (one `i18n_<locale>_gen.c` per `po/*.po`: Spanish, `es-US`, since G4); `i18n_catalog()`,
  `_count()`, `_at()` read it. A draft catalog (`preview` 1: not complete and reviewed) sits
  inside `#ifndef I18N_NO_DRAFTS`, which a release firmware defines (`cmake/alarm_firmware.cmake`)
  and the English preview walk too, so only a development build offers it (I18N-005). An
  entry's `text` carries two flags the lookup ignores: `I18N_ENTRY_PLURAL` and `I18N_ENTRY_WEB`
  (the Panel Manager's pages use it). A variant of English (`en-GB`) holds only what it writes
  differently and falls back to the English for the rest (docs/features/37 I18N-038); with one
  built in, `i18n_language_name(NULL)` is "English (US)".
- **The Panel Manager's words:** `i18n_web_json()` writes a catalog's web entries as one JSON
  document a piece at a time (`{"locale", "plural", "entries": {"<hash hex>": text or [forms]}}`),
  which the panel sends as `/i18n/<locale>.json`: the pages' words take no second copy in the
  image (docs/features/37 I18N-031).
- **Regions:** `i18n_region("US")` / `("es-US")` gives the region's default clock, first day of the
  week, decimal and grouping separators, minimum grouping digits and temperature unit (21 curated
  regions from CLDR 48, one sorted const table in `src/i18n_region.c`).
- **Dates:** `i18n_date()` formats an `i18n_civil_t` with a CLDR-subset pattern (`EEEE EEE MMMM
  MMM MM M dd d y yyyy h hh H HH mm ss a`, `'literal'`, `''`). Month and day names and AM/PM are
  catalog entries (contexts `month`, `month short`, `weekday`, `weekday short`, `day period`;
  English is the source); the patterns are catalog entries too, so the caller passes the one it
  got from the catalog. A date that opens with a weekday or month name starts with a capital
  (CLDR's stand-alone form: "Sábado, 19 de septiembre"). No libc time functions.
- **Numbers:** `i18n_number()` prints a value scaled by 10^decimals with the region's separators.
- **Markers:** `I18N_NOOP`, `I18N_NOOP_C`, `NOTR` for static tables the extractor must see.

## Public API
| Header | What it offers |
|---|---|
| `include/i18n/i18n.h` | lookup, plurals, formatter, UTF-8, catalogs |
| `include/i18n/i18n_date.h` | regions, `i18n_date()`, `i18n_number()` |

## Depends on
- Project components: none.
- ESP-IDF: none (portable).

## Options
None.

## Rules
- Plain C11: no malloc, no globals (const data only), no RTOS or ESP-IDF headers; the host build
  stays warning-free.
- Never edit `catalogs/i18n_catalogs_gen.c` by hand once the generator writes it.

## Tests
`i18n` (`test_i18n.c`, tags `I18N-001..004`, `-008`, `-010`, `-037`): the hash vectors, lookup
and the English fallback, context separating two meanings of "Open", plural categories for every
rule against the CLDR samples, form selection, the formatter (reordered, repeated, missing,
braces, `%s`/`%n` copied literally, numbers), and truncation and invalid input in the formatter
and each UTF-8 helper.

`i18n_date` (`test_i18n_date.c`, tags `I18N-016`, `I18N-017`): region lookup by tag and by BCP 47
tag, the region table's invariants, the English strings the UI shows ("Sep 19, 10:41 PM",
"22:41", "12 AM", "07"), literals, out-of-range fields, names from a catalog, truncation on a
character, decimals, grouping per region and the 64-bit extremes.

## Language packs (docs/features/37 language-packs.md)
`i18n_pack_open()` (`include/i18n/i18n_pack.h`, `src/i18n_pack.c`) is the strict reader of a pack's
payload: it refuses anything the format does not allow, reads nothing outside the bytes given,
allocates nothing, and fills an `i18n_pack_t` whose `catalog` is used in place by `i18n_text()`.
`i18n_pack_matches()` says whether the pack was made from this firmware's English.
`i18n_tag_valid()` checks a locale tag (2-15 of `[A-Za-z0-9-]`).
