# Documentation

| Folder | What | For |
|---|---|---|
| [RoboAlarms/documentation](https://github.com/RoboAlarms/documentation) | The User and Installer Guides, the Flasher and Panel Manager guides: their own repository, an Astro site published at <https://docs.roboalarms.com> | people who install and use a panel |
| [`features/`](features/README.md) | One design document per feature (requirements with IDs, design, tests, tasks), with the index, the roadmap and the current status | people working on the code |
| [`BACKLOG.md`](BACKLOG.md) | Everything left to do in one ordered list: features, checks owed on a panel, parts and services, decisions | people working on the code |
| [`bugs/`](bugs/README.md) | Bug write-ups: symptom, cause, fix and how it was proven | people working on the code |
| [`sensors/`](sensors/README.md) | The sensor notebook: what real sensors send and how they behave, ideas for later | people working on the code, and anyone adding a sensor |
| [`research/`](research/) | Background research behind decisions: [add-on wiring](research/AddOnWiringResearch.md), [offline speech](research/AnnunciationResearch.md), [Flasher UX](research/FlasherUXResearch.md) | people working on the code |
| [`hardware/`](hardware/README.md) | Where to get the boards' vendor documentation (the files are kept locally, not published) | people working on the code |
| [`BRAND.md`](BRAND.md) | The RoboAlarms identity: mark, colours, type | everyone who makes something that carries the name |

The build and the tests are in [CONTRIBUTING.md](../CONTRIBUTING.md), the rules the code follows in
[AGENTS.md](../AGENTS.md) (for people and AI agents alike);
security reports go by [SECURITY.md](../SECURITY.md).
