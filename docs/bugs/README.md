# Bugs

Open defects found by testing on the real panel, with enough detail to resume the work in a
new session or hand it to someone else.

One file per bug: `BNNN-short-name.md`. Each one carries the symptom, the evidence actually
captured from the device, the root cause, what has already been changed, what remains, and how
to verify. When a bug is fixed and verified on hardware, note that at the top and keep the file
— the evidence is worth more than a tidy folder.

The panels named in the reports (board 3, `bench-panel`) are the maintainers' development panels: 7-inch CrowPanels (CrowPanel Advanced 7" V1.1, P4 v1.3) unless a report says otherwise, such as B009's 4-inch E32R40T. A name stays as the evidence of where something was seen.

## Resuming
Read the bug file top to bottom — its current status and verification sections identify edits already
made and any remaining limits. B001 is committed (`6745fa5` and later); B002-B006 were committed and pushed
as `8367725` (2026-09-22) and are in every image installed since, but not yet checked on a panel. Use `git status`
and the current bug report to distinguish completed work from residual investigations.
Checks still owed on a panel are rows in the [backlog](../BACKLOG.md), section 3.

## Ground rules when working on the panel
- Flash only while the panel is **disarmed**, and only when the person you work for has just said to.
- Never guess codes at the console: five wrong attempts lock the keypad for five minutes and
  every attempt is logged and reported.
- Read `PANEL.local.md` (git-ignored) for this board's port, silicon revision and backup
  location. Without it, ask — do not assume.
- Never enable eFuse Secure Boot or flash encryption, and never run a C6 co-processor update
  unless the panel's owner asks explicitly. Both can brick the board permanently.
- Do not change `partitions.csv`: it forces a full erase and loses configuration, users and the
  event log.
